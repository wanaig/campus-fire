# 校园消防设施巡检管理系统

面向学校保安处的消防设施建档、二维码现场巡检、异常整改和统计预警系统。

## 系统组成

| 模块 | 目录 | 说明 |
|------|------|------|
| Java 后端 | `backend/` | Spring Boot 2.7 + MySQL 8 + Redis，JWT 鉴权 |
| 管理后台 | `admin-web/` | React + Fluent UI，管理员使用（PC 浏览器） |
| 微信小程序 | `miniprogram/` | 保安巡检端 + 数据采集端 |

## 功能总览

**管理后台（admin）**
- 数据看板：设施总数、待巡检、逾期任务、待整改、巡检完成趋势、设施类型分布、保养到期提醒
- 设施档案：查询、二维码批量生成与打印
- 巡检管理：任务列表（状态/关键词筛选、逾期标记）、巡检计划（新建计划、按计划生成任务、指派保安）
- 整改管理：整改单筛选、填写整改结果并闭环
- 用户管理：账号列表、新建保安/采集员账号
- 大字号无障碍模式、桌面/手机响应式

**微信小程序（保安 guard）**
- 巡检任务列表（状态筛选、逾期提示、下拉刷新）
- 扫设施二维码开始巡检（二维码校验 + 定位校验，中途退出可恢复会话）
- 检查项正常/异常填写、备注说明
- 现场拍照留痕（强制摄像头拍摄，禁止相册选择，含时间/设备/定位元数据与 SHA-256 哈希）
- 保存草稿（弱网/中断后可恢复）
- 提交巡检（异常项自动生成整改单）
- 整改单查看

**微信小程序（数据采集员 collector）**
- 新建设施档案（类型/位置/品牌/坐标采集），保存后生成专属巡检二维码
- 设施初始拍照留痕（强制摄像头拍摄、拍摄时定位、保存档案时自动上传，含时间/设备/GPS 元数据与 SHA-256 哈希，照片加水印存档）
- 编辑档案时可补拍或删除初始照片；采集列表、管理后台与访客扫码查询均可查看初始照片

## 快速开始（一键启动）

### 环境要求

- JDK 8+、Maven 3.8+、Node.js 18+、Docker Desktop、微信开发者工具（体验小程序时）

### 启动

```powershell
# 在项目根目录执行
powershell -ExecutionPolicy Bypass -File deploy\start-all.ps1
```

脚本会自动：启动 MySQL/Redis 容器 → 构建并启动后端（8080）→ 安装依赖并启动管理后台（5173）→ 打开浏览器。

### 停止

```powershell
powershell -ExecutionPolicy Bypass -File deploy\stop-all.ps1        # 停止全部（含数据库容器）
powershell -ExecutionPolicy Bypass -File deploy\stop-all.ps1 -KeepDocker  # 只停后端和前端
```

### 默认账号（首次启动自动创建演示数据）

| 角色 | 账号 | 密码 | 用途 |
|------|------|------|------|
| 管理员 | admin | 123456 | 管理后台 |
| 保安 | guard01 ～ guard10 | 123456 | 小程序巡检 |
| 数据采集员 | collector01 ～ collector10 | 123456 | 小程序设施建档 |

演示数据含 6 个示例设施（广州坐标）和今日巡检任务。微信开发者工具默认模拟定位也是广州，可直接体验定位校验。

## 微信小程序使用

1. 打开微信开发者工具 → 导入项目 → 选择 `miniprogram` 目录（AppID 可用测试号/游客模式）
2. 详情 → 本地设置 → 勾选 **"不校验合法域名"**
3. 模拟器直接用默认地址即可；**真机调试**时把 `miniprogram/utils/config.js` 改为电脑局域网地址（如 `http://192.168.1.100:8080/api`），手机与电脑连同一 Wi-Fi
4. 用 guard01 ～ guard10 中任一账号登录 → 任务列表 → 扫码巡检
   - 模拟器无摄像头时可在"我的"页开启**演示模式**（定位校验放宽到 10 公里）
   - 测试二维码：管理后台 → 设施档案 → "打印二维码" → 用模拟器扫码或另用手机扫

```powershell
# 后端单元测试
Set-Location backend; mvn test

# 端到端冒烟测试（需先启动数据库，脚本会自行启动/停止后端）
powershell -ExecutionPolicy Bypass -File deploy\e2e-smoke.ps1
```

E2E 覆盖 30+ 项断言：登录、任务下发、扫码校验、定位校验、检查项、草稿、拍照留痕（相册来源拒绝）、采集员设施初始照片（权限/防造假约束/清单/删除）、提交、异常自动整改单、整改闭环、看板统计等。

## 常见问题

- **接口请求一直转圈**：若电脑运行 Clash/V2Ray 等代理（TUN 模式），可能劫持 `localhost`。系统默认已使用 `127.0.0.1` 规避；如仍有问题请为 `127.0.0.1`/`localhost` 添加直连规则。
- **MySQL 容器反复重启**：Docker Desktop 不稳定时会连累容器（数据在 `deploy/data` 卷中不会丢失），重新执行 start-all 即可。
- **后端 8080 被占用**：`netstat -ano | findstr :8080` 找到 PID 后 `taskkill /PID <pid> /F`。

## 生产部署要点

- 通过环境变量覆盖：`DB_PASSWORD`、`JWT_SECRET`、`SEED_ADMIN_PASSWORD`，并设置 `SEED_ADMIN_ENABLED=false`、`SEED_DEMO_ENABLED=false` 关闭演示账号数据
- `CORS_ALLOWED_ORIGINS` 配置真实前端域名；建议前后端同域经 Nginx 反代
- 管理后台 `npm run build` 产物在 `admin-web/dist`，可静态托管
- 巡检照片存储路径 `INSPECTION_PHOTO_STORAGE_PATH` 请指向持久化磁盘

## 核心约束（防造假设计）

- 巡检照片不得从相册选择，只允许现场调用摄像头；服务端校验拍摄来源、拍摄时间窗口、JPEG/PNG 文件签名和 SHA-256 哈希
- 采集员设施初始照片遵循同一套防造假约束（仅现场相机、拍摄时间窗口、文件签名、哈希与水印），仅允许采集员/管理员上传，照片定位与设施档案坐标比对
- 正式巡检必须绑定设施二维码、定位信息（距设施超过阈值拒绝开始）和服务器时间
- 保安提交后的正式记录不能自行修改或删除
- 无障碍模式（大字号）不降低任何防造假校验
