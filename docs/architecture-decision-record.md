# 架构决策记录

## ADR-001：第一版系统形态

**状态：** 已采用  
**决定：** 管理后台、微信小程序、单体后端服务和 MySQL 数据库。

第一版优先保证业务闭环和部署简单，不拆分微服务。数据采集员与保安共用同一小程序，根据角色显示不同菜单。

## ADR-002：后端技术

**状态：** 已采用  
**决定：** Java 8 + Spring Boot 2.7.18。

当前开发电脑安装的是 JDK 8。Spring Boot 3 要求 JDK 17，会导致现有环境无法直接运行。待学校服务器环境确定后，可单独规划升级，不在首批工程初始化中混入版本迁移。

## ADR-003：数据和缓存

**状态：** 已采用  
**决定：** MySQL 8.0 保存业务数据，Redis 7 用于缓存、短期会话和重复提交控制。

数据库结构通过 Flyway 版本化迁移，禁止只在个人电脑手工修改表结构。

## ADR-004：接口形式

**状态：** 已采用  
**决定：** 使用 `/api` 前缀的 RESTful JSON 接口，并统一响应结构和错误码。

## ADR-005：部署方式

**状态：** 已采用  
**决定：** 开发环境使用 Docker Compose 启动 MySQL 和 Redis；应用可直接由 Maven 启动。正式环境后续提供完整容器化部署。

## ADR-006：防造假边界

**状态：** 已采用  
**决定：** 正式巡检必须绑定扫码会话、实时定位、服务器时间和现场摄像头照片。

只在前端隐藏相册入口不构成安全保证，后端还必须校验照片与巡检会话的绑定关系和必要元数据。

## 待甲方确认

1. 生产环境部署在校内服务器还是国内云服务器。
2. 访客可以查看到什么粒度的数据。
3. 现场定位允许误差范围。
4. 设施照片和巡检记录保存年限。
5. 是否需要学校统一身份认证。
